# 公众号文章自动采集任务进度

更新时间：2026-07-29

## 已确认目标

- 使用 `wechat-article/wechat-article-exporter` 的查询类 API，定时获取已关注公众号的最新文章基本信息。
- 采集范围为 19 个公众号；来源名单已由本机导出的 `公众号.json` 验证，包含公众号名称与 `fakeid`。
- 使用 GitHub Actions 全天运行，不依赖本地 Chrome 或电脑开机。
- 第一版仅负责采集、去重和保存 CSV，不下载正文、不调用大模型、不自动生成选题。
- 新增文章将供人工阅读，或由后续人工触发的 AI 选题筛选流程使用；筛选标准参照《选题搜集Prompt-双版本.md》。

## 已核对的上游能力与约束

- 查询接口为 `GET /api/public/v1/article?fakeid=...&begin=0&size=20`；返回文章链接、标题、作者、摘要、创建时间、发布时间等字段。
- 查询接口使用 `X-Auth-Key` 登录会话密钥认证；密钥约 4 天失效，需要重新扫码登录后更新 GitHub Secret。
- 公共站点的免费查询额度为每分钟 5 次；会员令牌 `X-Api-Token` 与登录密钥不同，第一版不使用。
- 单页最多获取 20 条消息。10 分钟内单个公众号发布超过 20 条的概率很低；如以后出现该情况，再增加分页补偿。
- 当前仓库为公开仓库，密钥不得写入脚本、配置文件、CSV、提交记录或 Actions 日志，只能保存为 GitHub Actions Secret `WECHAT_AUTH_KEY`。

## 推荐设计（待用户最终确认）

1. 将导出的公众号名单转换为仓库内精简配置，只保留 `nickname` 与 `fakeid`。
2. GitHub Actions 每 10 分钟启动一次，按固定顺序每隔约 15 秒查询一个公众号；19 个公众号在约 4 分半钟内完成一轮，低于每分钟 5 次的限制，并留出重试余量。
3. 每轮仅查询各公众号的第一页，将返回文章按链接主键、`aid` 辅助键去重。
4. 仅在发现新增文章时更新 CSV 并提交；无新增内容时不产生提交。
5. 遇到认证失效、限流或接口错误时保留既有 CSV，令工作流失败并在 Actions 日志中输出不含密钥的错误提示。
6. 使用工作流并发控制，避免上一轮延迟时出现两个任务同时修改 CSV。
