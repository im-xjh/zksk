# 转换通用规则

## 基本判断

convert 是写作后的可选环节。需要转 Word 时，先确认稿件类型和目标格式；若稿件较短或用户说明手动排版，则只输出 Markdown。

写作阶段应提前遵守目标转换器的 Markdown 限制，避免写完后再大改结构。

## 项目现有转换器

本项目已有三类转换流水线，执行前以项目内最新说明和实际文件为准。

### 根目录通用转换器

适用于“简报”类报告。支持两种正文字号预设：

- `small2`（小二/18pt）—— 标题二号，一级标题小二，正文小二。
- `3`（三号/16pt）—— 标题小二，一级标题小二，正文三号。

Windows 上优先使用 `.cmd` 启动器。

### 海淀周报转换器

用于海淀区意识形态周报。严格解析 Markdown：仅支持 `#`（一级标题）。文本若看起来像章节标题（如“一、……”）但未使用 `#` 将报错。图片必须独占一行。网络图片将被拒绝。

写海淀周报时，不要在 Markdown 中使用会破坏转换器的复杂结构。

### 境外敏感信息专报转换器

用于“境外敏感信息专报”，将 Markdown 草稿转换为带固定封面、目录和正文样式的 Word 文档。通过模板填充 `{{TOC}}` 和 `{{BODY}}` 占位符。

不支持图片、表格、三级及以上标题。

## 执行规则

1. 写作前确认是否需要 convert。
2. 写作时按对应转换器限制组织 Markdown。
3. 转换前检查标题层级、图片、表格、网络图片、占位符和文件名。
4. 转换后如用户要求，再检查 Word 是否生成成功。
5. 不主动推送或发布转换产物。

## 输出文件命名

若用户没有指定文件名，按稿件类型 profile 或所在目录既有命名习惯处理。不要为了统一而改动项目已有命名方式。
