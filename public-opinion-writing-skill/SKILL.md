# 舆情报告写作工作流

本 skill 借鉴 `writing-dna-skill` 的分层思路，稳定产出可报送、可核验的舆情报告材料。用户会在任务中说明稿件类型或模仿对象；若已说明，直接按对应 profile 执行；若未说明，只询问缺失的关键信息。

## 读取顺序

执行任务时按以下优先级读取要求：

1. 用户本次明确要求。
2. 用户提供的对标文章、批注和手动修改。
3. 本 skill 的 `profiles/` 中对应稿件类型 profile。
4. 本 skill 的通用规范文件。
5. 项目内现有转换器和格式说明。

若用户已经给出最新版正文，则以最新版正文为唯一基准稿，早先 AI 草稿只能作为历史参考，不能作为回退来源。

## 工作流路由

- 海淀周报：`search → writing → convert`。
- 天津摘编：`writing → convert`，默认不检索，除非用户明确要求补充核验。
- 统战：`search → writing → convert`。
- 其他约稿：`brainstorm → search → writing → convert`。

`brainstorm` 只在其他约稿中默认执行。固定的前三类稿件已经有工作流和范式，不主动扩展选题，除非用户要求先讨论角度。

## Brainstorm

只针对其他约稿默认执行。先拆用户指定的对标文章，再提出可采用的角度、结构和材料需求。拆解重点包括：标题方式、开头方式、事实铺垫方式、论证推进方式、材料密度、段落长度、结尾方式、哪些地方必须模仿、哪些地方只作参考。

## Search

按稿件类型 profile 执行。检索输出阶段区分事实材料、媒体观点、社媒观点和待核验信息。境外社媒检索必须先说明可见性边界。检索材料可以按平台列，正式舆论观点部分应按观点集合和立场差异组织，而不是按平台堆材料。

## Writing

写作阶段同步执行自检。事实、舆论、研判通常分开，面对简单议题，事实与舆论可以合并；舆论按观点类型归并。写完后删除万能句、过度升华、非必要引号、自造靶子式修正和写作提示语。

## Convert

根据 profile 指定方式转换。若稿件较短或用户说明手动排版，则只输出 Markdown。需要转 Word 时，先确认稿件类型，并在写作阶段提前遵守目标转换器的 Markdown 限制。

## 改稿保真

用户修改后的最新版正文是唯一基准稿。用户手动修改必须保留，用户批注在最新版正文基础上执行。改稿时遵守“最新版优先、批注局部处理、未批注部分不回退”的规则：用户已经改成的文字视为确认稿，用户批注要求调整的部分只在确认稿基础上修改，未被批注要求覆盖的内容保持现状。

## 相关文件

- `通用写作规范.md`：事实、舆论、研判、标题、语言和 AI 味控制。
- `通用检索规范.md`：事实核验、媒体引用、境外社媒检索和材料采用规则。
- `对标模仿规范.md`：其他约稿和对标文章拆解方法。
- `改稿保真规则.md`：用户手动修改、批注和局部改稿规则。
- `转换通用规则.md`：Markdown 到 Word 的通用转换判断。
- `profiles/`：海淀周报、天津摘编、统战、其他约稿四类稿件 profile。
- `templates/`：常用写作、检索和自检模板。
